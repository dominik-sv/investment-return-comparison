## What this is

A small research pipeline: how the distribution of long-horizon returns changes with
the holding period, for three views — `excess_wealth` (US market minus the 1-month
T-bill), `real_market`, `real_tbill`. `README.md` has the domain detail; read it for
the modelling rationale.

## Environment

- **Use `~/anaconda3/python.exe`** for everything. It has `pandas`, `numpy`, `scipy`,
  `tqdm`, `matplotlib`, `lseg-data`. The `python` on PATH is a bare Windows Store
  build without these.
- Jupyter for `run.ipynb`: `~/anaconda3/Scripts/jupyter.exe`.
- Not a git repo.

## Commands

```bash
# fetch raw data -> data/raw/  (plain HTTPS downloads, no credentials)
~/anaconda3/python.exe get_data.py

# run both sweeps for every series in config.SERIES -> data/processed/
# ~4-5 min for the full 1926- history; writes ~1.3 GB
~/anaconda3/python.exe process_data.py

# export compact JSON for the website (reads .npz, writes docs/data/*.json, ~2.3 MB)
~/anaconda3/python.exe export_web.py

# execute the driver notebook end to end
~/anaconda3/Scripts/jupyter.exe nbconvert --to notebook --execute --inplace run.ipynb --ExecutePreprocessor.timeout=600
```

No test suite / linter. To sanity-check a change quickly, run `process_data.py` with a
small `config.DAY_LONG` (e.g. `500`) — the sweep cost scales with it.

To render plots headlessly (they call `plt.show()`):

```python
import matplotlib; matplotlib.use("Agg")
import visualize; visualize.visualize_from_disk("excess_wealth", "common")
# then fig.savefig(...) per plt.get_fignums()
```

## Architecture

Flat modules, single source of truth in `config.py`. Pipeline: `get_data` → `data/raw/`
→ `process_data` → `data/processed/` → `visualize`.

- **`get_data.py`** — downloads and stores raw series; `load_*` readers have no network
  dependency. Sources: US market total return = Ken French `Mkt-RF + RF` (daily,
  1926-07); 1-month T-bill = Ken French monthly `RF`; US CPI = BLS `CUUR0000SA0` via a
  community mirror (`config.CPI_URL`) because FRED itself is unreachable from this
  environment — the FRED URL is noted in config as the primary if it works elsewhere.

- **`process_data.py`**
  - `levels()` builds every daily level series on the equity trading calendar.
    Monthly inputs (T-bill, CPI) are **held flat between observations**
    (`_step_to_calendar`) — for the T-bill this is a deliberate, slightly
    conservative model of holding each bill to maturity (no partial accrual).
  - `_sweep(level, ..., bench=None)` is the core: for every holding period 1..`DAY_LONG`
    calendar days it computes buy-and-hold window returns across all start dates.
    `common_start=True` fixes the start-date set to those admitting the longest
    horizon (horizons comparable to each other); `False` lets each horizon use every
    start it can (more data per point, cross-horizon bias). With `bench`, each value
    is `G_level − G_bench` — arithmetic **extra wealth per unit invested** vs. the
    benchmark, in %.
  - `SERIES_INPUTS` maps each series name → `(level source, benchmark source or None)`.
  - `compute_and_save(level, name, bench=None)` runs both sweeps and persists:
    `summary_{name}_{common,expanding}.csv` (small: n, 4 moments, `config.PERCENTILES`)
    and `distributions_{name}.npz` (large: the full ragged return arrays, float32,
    packed as horizons/offsets/values; `_unpack` upcasts to float64 on load — needed,
    float32 variance overflows at long horizons).

- **`visualize.py`** — `visualize(level, dist, summary, ...)` draws up to 5 panels
  (level, window fan, annualised fan, moments, `P(<0)`). Per-series options live in
  `_VIZ_OPTS`; `visualize_from_disk(name, method)` applies them. `excess_wealth` runs
  with `annualised=False, show_level=False`: an arithmetic difference of two compound
  returns has no meaningful compound-annual form, and annualising it can hit
  `(<0) ** fractional` → NaN. The fan bands are one solid shade per 10 percentile
  points; `config.ANNUAL_YLIM` clamps the annualised fan.

## Conventions / gotchas

- `data/processed/*.npz` are ~640 MB each and regenerated by `process_data.py`. Don't
  delete casually; don't attempt to host or commit them (see the website discussion in
  the conversation history — the plan is a precompute step emitting small JSON).
- All monthly→daily alignment uses forward-fill (step), never interpolation.
- Adding a series = add to `config.SERIES`, `process_data.SERIES_INPUTS`,
  `visualize._LABEL` + `visualize._VIZ_OPTS`, a `run.ipynb` viz cell, and
  `export_web.py`'s `_LABEL` / `_UNIT` (+ `_VIEWS` if it belongs in a website view).
- `export_web.py` is the only bridge to the website: `.npz` -> `docs/data/*.json`.
  `docs/` is what GitHub Pages serves (Deploy from branch -> main -> /docs); it holds
  `.nojekyll` + the JSON now, and the frontend (`index.html` + JS) later. The site
  renders those JSON files and nothing else, so presentation changes are
  frontend-only; new statistics/series need a re-export.
- `notes.md` is empty; ignore it.
